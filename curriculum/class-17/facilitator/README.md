# Guía del Instructor: Introducción a la Gestión de Proyectos Ágiles

## Objetivo de la Clase
Esta sesión marca el inicio de la fase de proyectos finales del curso. El objetivo principal es que los estudiantes comprendan cómo abordar un proyecto de desarrollo web de manera estructurada, utilizando metodologías ágiles y herramientas de documentación. Se enfatiza el uso estratégico de IA como herramienta de apoyo para análisis y documentación.

## Distribución del Tiempo (3 horas)

1. **Introducción y Demo** (45 min)
   - Presentación de conceptos AGILE (15 min)
   - Demo de Trello y GitHub Projects (15 min)
   - Ejemplo de documentación en Markdown (15 min)

2. **Explicación y Práctica** (45 min)
   - Escritura de historias de usuario (20 min)
   - Ejercicio grupal de análisis (25 min)

3. **Laboratorio Guiado** (90 min)
   - Formación de equipos (15 min)
   - Trabajo en documentación (45 min)
   - Revisión y retroalimentación (30 min)

## Conceptos Clave a Enseñar

### 1. Metodología Ágil
Framework iterativo que divide el desarrollo en sprints cortos, permitiendo adaptarse a cambios y entregar valor incrementalmente. Enfatizar los roles (Product Owner, Scrum Master, Team) y ceremonias básicas (Daily, Planning, Review).

### 2. Historias de Usuario
Descripciones breves y específicas de funcionalidades desde la perspectiva del usuario final. Deben seguir el formato "Como [rol] quiero [acción] para [beneficio]" y tener criterios de aceptación claros.

### 3. MVP (Minimum Viable Product)
Versión más simple de un producto que puede ser lanzada con suficientes características para satisfacer los usuarios iniciales y proveer retroalimentación para desarrollo futuro.

### 4. Documentación Técnica
Conjunto de documentos que describen los aspectos técnicos del sistema, incluyendo requerimientos, arquitectura, y guías de implementación. Debe ser clara, concisa y mantenible.

## Ejemplos a Utilizar

### 1. Historia de Usuario
```markdown
Como vendedor de la tienda
Quiero ver un dashboard con las ventas del día
Para identificar rápidamente los productos más vendidos

Criterios de Aceptación:
- Mostrar top 5 productos por cantidad vendida
- Actualizar datos cada 5 minutos
- Permitir filtrar por categoría
```

### 2. Documentación de Requerimiento
```markdown
## Sistema de Autenticación

### Descripción
Sistema de login para empleados de la tienda usando correo corporativo.

### Requerimientos Técnicos
- Validación de dominio @empresa.com
- Almacenamiento seguro de contraseñas
- Sesión con expiración de 8 horas

### Consideraciones
- Integración con sistema actual de empleados
- Soporte para múltiples dispositivos
```

## Glosario de Términos

- **Sprint**: Período fijo (usualmente 1-3 semanas) para completar un conjunto de tareas.
- **Backlog**: Lista priorizada de todas las funcionalidades deseadas del producto.
- **User Story**: Descripción de una funcionalidad desde la perspectiva del usuario.
- **Acceptance Criteria**: Condiciones que debe cumplir una funcionalidad para considerarse completa.
- **Scope**: Alcance definido del proyecto, qué se incluye y qué no.
- **Stakeholder**: Persona u organización con interés en el proyecto.

## Errores Comunes a Prevenir

1. **Alcance Poco Realista**
   - Síntoma: Historias de usuario muy amplias o ambiguas
   - Solución: Enseñar a dividir funcionalidades en tareas más pequeñas

2. **Documentación Excesiva**
   - Síntoma: Documentos muy largos con información redundante
   - Solución: Enfocarse en información esencial y mantener formato conciso

3. **Dependencia Excesiva de IA**
   - Síntoma: Copiar/pegar respuestas de IA sin análisis
   - Solución: Usar IA para generar ideas iniciales, pero refinar manualmente

4. **Falta de Criterios de Aceptación**
   - Síntoma: Historias de usuario sin condiciones claras de completitud
   - Solución: Establecer plantilla con criterios obligatorios

5. **Roles Mal Definidos**
   - Síntoma: Confusión sobre responsabilidades en el equipo
   - Solución: Definir y documentar roles claramente al inicio del proyecto
