CSS Moderno y Git — La base de frontend profesional

Variables CSS, validación nativa de formularios y el workflow Git que cualquier equipo te pedirá

1. CSS Variables — Un token para gobernarlos a todos

Define colores, espacios y radios en :root una vez. Un cambio actualiza todo el sitio.

:root {
  --color-primary: #0066cc;  ← definir una vez
  --space-md:     1rem;
  --radius:       8px;
}

button {
  background:    var(--color-primary);
  padding:       var(--space-md);
  border-radius: var(--radius);
}

2. Validación Nativa — El navegador valida, tú no escribes JS

Los atributos HTML dicen al navegador qué es válido. Sin una línea de JavaScript.

<!-- required: no puede estar vacío -->
<input type="text"  required>

<!-- type="email": debe ser email válido -->
<input type="email" required minlength="5">

<!-- pattern: debe matchear la regex -->
<input type="tel" pattern="[0-9]{9}" required>

<!-- select y checkbox también son validables -->
<select required><option value="">Elige</option></select>

3. Git Workflow Profesional — Nunca pushees a main directamente

El PR es donde el equipo revisa. Main solo recibe código aprobado.

git checkout -b feature/contacto-validado
# ... editar archivos ...
git add index.html css/styles.css
git commit -m "feat: agrega validación al form de contacto"
git push -u origin feature/contacto-validado
# → abrir Pull Request en GitHub → revisar → merge
git checkout main
git pull

4. Merge Conflict — No es magia, es elegir entre versiones

Cuando dos ramas modifican la misma línea, Git lo marca. Tú decides qué queda.

<<<<<<< HEAD
  background: blue; ← tu versión
=======
  background: red; ← versión de la otra rama
>>>>>>> main
1. Lee ambas versiones y entiende la diferencia
2. Elimina los marcadores <<< === >>> y deja solo lo que debe quedar
3. git add . + git commit -m "merge: resuelve conflicto"
CSS Variable Token definido con --nombre en :root. Se usa con var(--nombre).
pattern Atributo de <input> que recibe una regex. El navegador rechaza valores que no coincidan.
Pull Request Solicitud de merge en GitHub. Permite revisar código antes de integrarlo a main.
Merge conflict Dos ramas modificaron la misma línea. Git lo marca con <<< === >>> para resolución manual.
