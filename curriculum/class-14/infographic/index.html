Patrón Store — Estado centralizado con una API controlada

getState / setState / subscribe / notify — nadie toca el estado directamente

1. El Store — La API del estado global

Un objeto central que concentra todo el estado de la aplicación. Nadie lee ni escribe state directamente — todo pasa por los métodos.

const store = {
  state:     { items: [] },      // el estado — nunca tocar directo
  listeners: [],

  getState()          { return this.state; },
  subscribe(fn)       { this.listeners.push(fn); },
  notify()            { this.listeners.forEach(fn => fn(this.state)); },

  setState(newState)  {
    this.state = newState;  // reemplaza — no muta
    this.notify();          // avisa a todos los oyentes
  }
};
getState()
Leer. Nunca tocar state directo.
setState()
Cambiar. Dispara notify automático.
subscribe()
Registrar oyentes del estado.
notify()
Ejecuta todos los oyentes.

2. Inmutabilidad — Nunca mutar, siempre crear nuevo

Modifica el estado creando un nuevo objeto/array, nunca alterando el existente. Cada setState produce un estado nuevo.

// ❌ Mutación directa — rompe el patrón
state.items.push(nuevoItem);

// ✅ Agregar — crear nuevo array
store.setState({ ...store.getState(), items: [...store.getState().items, nuevoItem] });

// ✅ Eliminar — filtrar sin el item
store.setState({ ...store.getState(), items: store.getState().items.filter(i => i.id !== id) });

// ✅ Editar — mapear con cambio solo al target
store.setState({ ...store.getState(), items: store.getState().items.map(i => i.id === id ? {...i, ...cambios} : i) });

3. El Flujo — Subscribe → setState → UI actualizada sola

Registras la función de render como oyente. Cuando el estado cambia, el Store llama a render automáticamente — sin invocarla a mano.

function renderLista(state) {
  lista.innerHTML = state.items.map(i => `<li>${i.nombre}</li>`).join('');
}

store.subscribe(renderLista);   // ← registrar una vez

// Más tarde, al hacer clic en "Agregar":
store.setState({
  ...store.getState(),
  items: [...store.getState().items, nuevoItem]
});
// → store llama renderLista automáticamente

4. Por qué usar un Store

Sin Store: cualquier función puede mutar el estado y es difícil saber quién rompió la app. Con Store: hay un solo canal de entrada.

// Sin Store — estado disperso, difícil de rastrear
let items = [];
function agregar(item)  { items.push(item);         actualizarUI(); }
function eliminar(id)  { items = items.filter(...); actualizarUI(); }
// ¿Quién más modifica items? No lo sabemos.

// Con Store — un solo canal, trazable
function agregar(item)  { store.setState({ ...store.getState(), items: [...] }); }
function eliminar(id)   { store.setState({ ...store.getState(), items: [...] }); }
// La UI la actualiza el Store — no yo.
Store Objeto central con el estado de la app. Solo se accede mediante getState y setState.
Inmutabilidad No modificar el estado existente. Crear siempre un nuevo objeto/array con los cambios.
subscribe(fn) Registra una función que se llamará automáticamente cada vez que el estado cambie.
Spread (...) Operador que copia propiedades de un objeto en uno nuevo. Clave para actualizar estado sin mutar.
