Datos desde la web: fetch, Promesas y JSON

Tu Pokédex deja el array local y carga sus datos de una API real

1. fetch — los datos tardan en llegar

fetch pide datos a una URL y devuelve una Promesa: un "ticket" por datos que llegarán. La red tarda, pero JavaScript no se congela.

fetch("https://pokeapi.co/api/v2/pokemon/pikachu")
  .then(response => response.json())   // JSON → objeto
  .then(data => console.log(data))    // cuando LLEGAN
  .catch(() => mostrarError());

2. JSON y el adaptador

La API responde en JSON con su propia estructura (anidada). Una función adaptadora la traduce a tu forma limpia, para reusar crearTarjeta de C09.

// la API: { name, sprites:{front_default}, types:[{type:{name}}] }
function adaptarPokemon(data) {
  return {
    nombre: data.name,
    imagen: data.sprites?.front_default ?? "...",
    tipos:  data.types.map(t => t.type.name)
  };
}

3. Promise.all — varios a la vez

La rejilla necesita varios Pokémon, y cada uno es un fetch. Promise.all los pide en paralelo y espera a que todos terminen.

const promesas = ids.map(id =>
  fetch(`.../pokemon/${id}`).then(r => r.json())
);

Promise.all(promesas)
  .then(datos => render(datos.map(adaptarPokemon)));

4. El buscador de C09 sigue vivo

El render y el filtro de C09 no cambian: solo cambia de dónde vienen los datos. La rejilla ahora vive de la web.

buscador.addEventListener("input", () => {
  const filtrados = pokedex.filter(   // antes: pokemonLocal
    p => p.nombre.includes(buscador.value.toLowerCase())
  );
  render(filtrados);
});
Asincronía Los datos tardan (la red) y el programa sigue sin congelarse.
fetch / JSON Pide datos a una URL; llegan en JSON, que se convierte a objeto.
Adaptador Traduce la estructura de la API a tu forma limpia.
Promise.all Espera a que varias promesas terminen (carga en paralelo).
