Manejo de Excepciones — Código robusto que no se rompe en producción

try/catch/finally y throw para controlar qué pasa cuando algo falla

1. try / catch / finally — La estructura base

try intenta ejecutar código. Si lanza un error, catch lo captura. finally se ejecuta siempre, sin importar el resultado.

try {
  const html = procesarMarkdown(editor.value);
  preview.innerHTML = html;
} catch (error) {
  // Se ejecuta si procesarMarkdown() lanza un error
  mostrarMensaje(`Error: ${error.message}`);
} finally {
  // Se ejecuta SIEMPRE — éxito o fracaso
  spinner.style.display = "none";  // ocultar cargando
}
try
Código que puede fallar. Si falla, salta al catch.
catch
Captura el error. Recibe el objeto con message y stack.
finally
Siempre se ejecuta. Ideal para limpiar estado.

2. throw — Lanzar errores con intención

No esperes a que JavaScript detecte el error. Si los datos son inválidos, lánzalo tú con un mensaje claro.

function parsearNumero(valor) {
  if (!valor || valor.trim() === "") {
    throw new Error("El campo no puede estar vacío");
  }
  const numero = parseFloat(valor);
  if (isNaN(numero)) {
    throw new Error(`"${valor}" no es un número válido`);
  }
  return numero;
}

try {
  const monto = parsearNumero(inputMonto.value);
} catch (e) {
  errorLabel.textContent = e.message;  // muestra el mensaje al usuario
}

3. El Objeto Error — Qué información trae

new Error(mensaje) crea un objeto con propiedades que ayudan a depurar. console.error(e) muestra la traza completa en DevTools.

try {
  procesarDatos(null);
} catch (e) {
  console.log(e.name);     // "Error" (o "TypeError", "RangeError"…)
  console.log(e.message);  // "Cannot read properties of null"
  console.log(e.stack);    // traza con líneas del archivo donde ocurrió

  // Usar instanceof para distinguir tipos
  if (e instanceof TypeError) {
    // error de tipo: null, undefined, método inexistente
  }
}

4. Cuándo capturar — y cuándo no

Capturar todos los errores sin criterio oculta bugs. Solo captura cuando puedes hacer algo útil con el error.

Capturar cuando…
  • El input viene del usuario y puede ser inválido
  • Llamas a una API externa o lees localStorage
  • Puedes mostrar un mensaje claro al usuario
  • Puedes recuperar el estado o reintentar
No capturar cuando…
  • El error indica un bug en tu propio código
  • El catch está vacío o solo tiene console.log
  • Oculta el error sin dar feedback al usuario
  • No puedes hacer nada útil con él
Excepción Evento que interrumpe el flujo normal. Puede ser del sistema o lanzada con throw.
throw Lanza manualmente una excepción. Detiene la ejecución y pasa al bloque catch.
finally Se ejecuta siempre al salir del try/catch, sin importar si hubo error o no.
stack trace Traza de ejecución que indica qué archivo y línea originaron el error.
