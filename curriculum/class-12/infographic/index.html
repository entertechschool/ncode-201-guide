Manejo de Errores y Estados

De una app frágil a una robusta — y tu primer README

1. try / catch — la red de seguridad

El código que puede fallar va en try; si algo sale mal, catch lo atrapa y la app sigue viva.

try {
  const response = await fetch(url);
  const data     = await response.json();
  render([adaptarPokemon(data)]);
} catch (error) {
  mensaje.textContent = error.message;
}

2. fetch NO falla en 404 → revísalo

fetch solo falla si no hay red. Un 404 llega con ok=false: hay que revisarlo y lanzar el error con throw.

if (!response.ok) {                  // 404, 500…
  throw new Error(`No se encontró "${nombre}"`);
}
// throw salta directo al catch

3. finally + estados de UI

finally corre SIEMPRE — ideal para ocultar el spinner pase lo que pase. La app comunica su estado en todo momento.

⏳loadingCargando…
✅successla tarjeta
❌errorNo se encontró
🔍emptybusca algo

4. Markdown — documenta tu proyecto

Todo repo profesional lleva un README.md escrito en Markdown: títulos, listas, links y código.

# Pokédex
Buscador que consume la PokeAPI.

## Tecnologías
- JavaScript (fetch, async/await)
- [PokeAPI](https://pokeapi.co/)
