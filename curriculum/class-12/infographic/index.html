Manejo de Errores y Estados

De una app frágil a una robusta — y tu primer README

1. try / catch / finally — la red de seguridad

El código que puede fallar va en try; si algo se rompe, catch lo atrapa y la app sigue viva. finally corre siempre: ideal para ocultar el spinner.

spinner.classList.remove("hidden");   // ⏳ cargando
try {
  mostrarResultado(await buscarPokemon(nombre));
} catch (error) {            // algo se rompió (sin red)
  mensaje.textContent = "Algo salió mal.";
} finally {
  spinner.classList.add("hidden");    // ✅ corre SIEMPRE
}

2. fetch NO falla en 404 → revísalo

fetch solo falla si no hay red. Un 404 llega con ok = false: hay que revisarlo con response.ok y lanzar el error con throw.

if (!response.ok) {                  // 404, 500…
  throw new Error(`No se encontró "${nombre}"`);
}
// throw salta directo al catch

3. Cada situación, su estado de UI

Una app profesional siempre dice en qué estado está. El finally oculta el spinner pase lo que pase. La búsqueda tiene cuatro respuestas posibles:

✅Éxitola tarjeta del Pokémon
❌No encontrado404 → "No se encontró"
📡Sin rederror de carga
