Módulos ESM y cierre del proyecto

Organiza tu app en piezas, confirma antes de borrar y déjala lista para mostrar

1. export / import

En vez de variables globales, cada archivo comparte con export y pide con import. Cada módulo tiene su propio ámbito: se acaban los choques de nombres.

storage.js — comparte
export function guardar() {
  localStorage.setItem(CLAVE, ...);
}
ui.js — pide
import { guardar }
  from "./storage.js";

2. Un archivo, una responsabilidad

Repartes la app en piezas claras con un único punto de entrada. El navegador arma el resto siguiendo los import.

js/
├── models/Template.js # la clase
├── state.js # estado + lógica
├── storage.js # guardar / cargar
├── ui.js # render + listeners
└── app.js # arranque
<!-- un solo script -->
<script type="module" src="js/app.js"></script>

3. ESM necesita un servidor

Los módulos no cargan al abrir el HTML con doble clic (file://). Usa un servidor local — o GitHub Pages, que funciona sin problema.

# opción rápida en la carpeta del proyecto
python -m http.server
# o la extensión Live Server de VS Code

4. Modal propio para confirmar

Antes de una acción irreversible (borrar), muestras tu propio modal (HTML + Tailwind). Guardas la acción en una variable para que el mismo cuadro sirva para todo.

function pedirConfirmacion(mensaje, accion) {
  textoModal.textContent = mensaje;
  accionPendiente = accion;        // qué hacer si acepta
  modal.classList.remove("hidden");
}
