async/await y búsqueda en la API

Reformular las promesas y hacer crecer tu Pokédex

1. De .then a async/await

Misma promesa de C10, escrita como pasos secuenciales. async/await no reemplaza a las promesas: las hace más legibles.

C10 — .then
fetch(url)
  .then(r => r.json())
  .then(data => ...);
C11 — async/await
const response = await fetch(url);
const data = await response.json();

2. Reformular la carga

El Promise.all de C10, ahora con await: se lee de arriba a abajo.

async function cargarPokedex() {
  const datos = await Promise.all(ids.map(obtenerPokemon));
  pokedex = datos.map(adaptarPokemon);
  render(pokedex);
}

3. De filtrar a buscar en la API

El buscador deja de filtrar lo local y pasa a consultar la API por nombre: encuentra cualquier Pokémon, no solo los de tu rejilla.

async function buscarPokemon(nombre) {
  const data = await obtenerPokemon(nombre.toLowerCase());
  return adaptarPokemon(data);
}

4. La colección crece

pokedex es el estado de tu app. Cada búsqueda exitosa lo hace crecer (sin duplicar), y render lo refleja.

if (!pokedex.some(p => p.nombre === pokemon.nombre)) {
  pokedex.push(pokemon);   // crece la colección
}
render(pokedex);
async / await Escribir promesas como pasos secuenciales. await pausa hasta que resuelve.
Azúcar sintáctico No reemplaza a las promesas: es la misma lógica, más legible.
Buscar en la API Pedir un recurso por nombre, no filtrar lo que ya tienes.
Estado (pokedex) La colección que crece según lo que el usuario busca.
