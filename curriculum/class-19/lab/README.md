# Laboratorio 19: Auditoría + Sprint Final + Ensayo Final

## Objetivo

Guiar a los equipos en una última ronda de mejoras estratégicas, usando herramientas reales de colaboración (GitHub Issues) para auditar su propio proyecto, implementar mejoras y preparar una presentación convincente para la demo final.

## 🧩 Parte 1 (60 min) -  Auditoría y Revisión Cruzada vía GitHub Issues

**Actividades:**

1. Cada equipo realiza una autoevaluación rápida de su proyecto, identificando aspectos críticos a mejorar (usabilidad, bugs, flujos incompletos, etc.).
2. Abrir al menos **3 issues en GitHub** en su propio repositorio:
   * Cada issue debe describir claramente el problema y proponer una mejora.
3. Luego, cada equipo revisa el repositorio de otro grupo y crea **1 issue externo**, aportando feedback desde la mirada de un usuario externo.

✅ *Producto esperado:* Mínimo 4 issues por equipo (3 internos + 1 externo), escritos con claridad y utilidad.


## 🧩 Parte 2 (90 min): Sprint de Implementaciones y Correcciones

**Actividades:**

* Cada equipo prioriza sus issues y trabaja en resolver al menos 2 dentro del sprint.
* El instructor estará disponible para desbloquear dudas, revisar decisiones o facilitar pair programming.
* Se promueve uso del tablero en Trello para visibilidad del progreso.

✅ *Producto esperado:* Mínimo 2 issues cerrados por equipo con commits asociados y mensajes claros.


## 🧩 Parte 3 (30 min): Simulación de Demo + Feedback Técnico

**Actividades:**

* Cada equipo hace una presentación breve (5 min máximo):

  * ¿Qué mejoraron hoy?
  * ¿Qué parte del producto creen que está más sólida?
  * ¿Qué parte genera aún incertidumbre?
* Instructores y compañeros dan feedback breve, técnico y empático.

✅ *Producto esperado:* Narrativa inicial definida para la demo final + registro de feedback.

---

## 📝 Instrucciones de Envío

Al finalizar el laboratorio, cada equipo debe subir un archivo llamado `demo-plan.md` en la raíz de su repositorio. Este archivo debe contener:

### ✅ 1. Lista de funcionalidades clave

Enumerar **3 funcionalidades principales** que debe mostrar el proyecto en la demo final. Para cada una incluir:

* Nombre de la funcionalidad (ej. “Reservar cita”, “Agregar producto al carrito”).
* Breve descripción de lo que permite al usuario hacer.

### 🔧 2. Plan técnico de cierre

Describir el plan de trabajo desde hoy hasta la presentación final, incluyendo:

* ¿Qué queda pendiente por implementar o mejorar en cada funcionalidad?
* ¿Quién se encargará de cada parte? (roles asignados)
* ¿Qué herramientas o estrategias usarán para organizar el trabajo? (issues, GitHub Projects, reuniones, etc.)

### ⤴️ 3. Entrega en Canvas:

1. Link al repositorio con:
   - `demo-plan.md` completo
